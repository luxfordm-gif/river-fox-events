## Stack & build

- **Vite + React 18 + TypeScript + Tailwind + shadcn/ui.** Use **npm**, not bun (bun lockfiles were intentionally removed).
- `npm run build` runs `vite build` → `scripts/prerender.mjs` → `scripts/postbuild.mjs`. The postbuild step is what writes per-route static HTML, the sitemap and robots.txt — never edit those output files directly.
- Hosting: Netlify (apex `riverfoxevents.co.uk` primary, www redirects). DNS on Cloudflare in DNS-only / grey-cloud mode so Netlify can issue Let's Encrypt SSL.
- **Each page loads only its own code (speed pass, 2026-11-13).** Before, every page and all 17 articles were one 915KB file (262KB compressed) on every visit; now a page downloads 80-150KB, and adding articles doesn't make other pages heavier. Pages are listed once in `PAGES` in `src/App.tsx` (each a `lazyPage(() => import(...))` from `src/lib/lazyPage.tsx`); add a new page there. Article texts are `lazyPage` too, in `src/data/articles/index.tsx`. `main.tsx` waits for the current page's code before React takes over the prerendered HTML (no blank flash), and a finger or mouse on a link starts fetching that page's code. The footer, area links and router use the light town list `src/data/locations/towns.ts` (slug and name; `src/test/towns.test.ts` keeps it matching `LOCATIONS`), so the full town copy loads only on town pages. One stylesheet for the whole site (`cssCodeSplit: false`: split stylesheets can load in a different order and change which rule wins; one file is ~25KB and cached once). `public/_headers` lets browsers keep `/assets/*` for a year (the build renames a file whenever it changes). The "message sent" note (sonner) loads on the first tap or key press. Unused shadcn/ui parts and 38 unused packages were removed; only `button`, `carousel` and `sonner` remain in `src/components/ui/`.
- **Old-domain redirects:** `lollipopballoonssurrey.co.uk` (+ www) is a domain alias on the same Netlify site. Its path-level 301s are generated by postbuild from **`scripts/legacy-redirects.mjs`** into the top of `dist/_redirects` (one forced rule per location town, since Netlify placeholders can't sit mid-segment like `balloon-arches-near-:town`); anything unmatched goes to `/`. Edit that file, not `public/_redirects`. When a balloons page exists, repoint `/services/balloons` there.

## SEO — `src/seo/routes.ts` is the single source of truth

Per-route titles and descriptions live in `src/seo/routes.ts`. The postbuild step reads that file and injects the right `<title>`, meta, OG/Twitter and JSON-LD into each prerendered HTML file. **Edit `routes.ts`, then run the build — don't hand-edit `dist/` HTML.**

Targets:

- **Title patterns (Matt, 2026-11-10):** service pages `[Service] in Surrey | River Fox Events` (except `Commercial Christmas Decorations | River Fox Events`, kept under 60 characters), town pages `Party Styling in [Town] | River Fox Events` (town as the page copy writes it: "Walton-on-Thames", "Brighton & Hove"), Contact `Contact Laura | River Fox Events`, journal posts `[Post title] | River Fox Events` (post titles read like post titles; don't force title case on them). Titles live only in `routes.ts`; town and article pages re-apply that same string after load, and `src/test/page-titles.test.ts` checks the patterns. The town pages sharing "Party Styling in" is deliberate, so the uniqueness rule below doesn't apply to them.
- **Title:** ≤ 60 chars (Google truncates beyond that on desktop; mobile is tighter). Always end `| River Fox Events`. Front-load the keyword + location. Each page's title must be visibly distinct from the others — no two pages should share their first 4–5 words.
- **Meta description:** 150–160 chars. Front-load keyword + location. Same uniqueness rule — don't open two pages with the same phrase. Avoid generic openings like "Bespoke X across Surrey…" repeated verbatim across pages; vary the entry angle (trust signal, specific service, named clients, an outcome).
- **H1:** distinct per page. Don't fall back to the "[Service] stylist, based in Surrey." pattern — it makes pages feel near-identical to both crawlers and humans.
- **Hero sub-copy (the paragraph below the H1):** also distinct per page, ideally with a different opening word from the H1.
- **URLs:** Netlify serves trailing-slash URLs (`/childrens-parties/`). Keep canonicals consistent with that, and **every internal link must use the trailing slash** too (a test enforces it). Unknown addresses get `dist/404.html` with a real 404 status via the last rule in `public/_redirects`; don't put the old `/* /index.html 200` SPA fallback back, it makes Google see "soft 404s".

**Banned / capped vocabulary** (applies to titles, metas, H1s and hero sub-copy):

- "Bespoke" — banned from all titles. Max once per meta description. Free in body copy (it is Laura's own word).
- "Luxury" — max twice across all page titles site-wide.
- "From £300" — appears in a maximum of 6 page metas site-wide.
- Banned filler phrases (never use): "If you're looking for…", "Look no further…", "We pride ourselves on…", "Our team of experts…", "the perfect party".
- Banned praise words (brand book v2, everywhere in Laura's own copy): "stunning", "amazing", "wow factor", "show-stopping". Also no emojis, no exclamation marks, no "IP" / "licensed" / "unlicensed" for character themes (name the theme: "a Wonka party"). **Client review quotes are exempt:** reviews are shown word for word, never edited, even when they say "stunning" or "amazing". Review cards cap a quote at `--review-lines` (7) with an ellipsis so cards stay even; the words aren't changed, the full text stays in the page, and the whole card opens the review on Google (Matt, 2026-11-13).
- **Words people search for come first** in headings, descriptions and captions (SEO work, November 2026): balloon decorations, balloon arch, balloon garland, balloon wall, number stack, kids party decorations, milestone birthday decorations, 50th birthday decorations, shimmer wall / sequin wall hire, party styling in [town], corporate event styling, Christmas door garlands. The home title is `Party & Event Styling in Surrey | River Fox Events`.

**Client-locked copy rules (Laura, 2026-05-21).** These apply everywhere — body copy, hero copy, SEO metas, alt text, FAQs, location pages:

- **Em dashes (—) are banned.** Use a hyphen (-) instead. The entire `src/` tree was converted on 2026-05-21; don't reintroduce them.
- **"Design-led" is banned** (too industry, not consumer-friendly). Use **"thoughtfully styled"** in body copy and **"bespoke"** in SEO metas.
- **"From scratch" is banned.** Use **"individually designed"**.
- **"Elevated"** — use as little as possible. Allowed sparingly, never as the headline word.
- **Bullet points start with a capital letter** (sentence case), even when the list finishes a lead-in sentence ending in a colon (Matt, 2026-11-09). `src/test/sentence-case-bullets.test.ts` fails the test run if a `<li>` opens with a lowercase letter. The space between bullets in articles is the `--gap-list-item` token.

**Uniqueness rule — applies to titles, metas, H1s, hero sub-copy and image alt text.** Before writing new copy for a page, skim existing pages and make sure the first ~5 words of the new draft don't echo any other page. This protects against duplicate-content signals and keeps the writing feeling considered rather than templated.

## Design system - no one-off values (Matt, 2026-11-08)

Every reusable component and page, the Christmas page included, takes its typography and corners from the design system in `src/index.css`. **Never hard-code a font size, line height, letter-spacing, weight, font family or corner radius in a component.** `src/test/design-system.test.ts` fails the test run if one appears (inline style, Tailwind `text-[15px]` / `leading-*` / `tracking-*` / `font-light` / `rounded-[12px]`, or a raw value in a stylesheet).

Plus `t-accent` (italic words in a heading), `t-wordmark` / `t-wordmark-lg` (logo), `t-icon`. Weights `--fw-regular` (headings, body), `--fw-medium` (labels, buttons, nav, form fields, wordmark), `--fw-bold` (`<strong>` only). The sizes are the site's pre-restructure ones: a trial "even scale" and bold labels were rejected the same day as too big and shouty, so don't enlarge headings or embolden labels without showing Matt first. Serif is never for long reading.
- **Headings are Regular (400)**; light (300) read too thin in the real Fraunces. Body sizes are the same on phones as desktop. ## Location pages

Location data lives in `src/data/locations/<slug>.tsx` and is built via the `makeLocation()` helper in `_makeLocation.tsx`. Each location must have a unique `uniqueSeoDescription`, `uniqueHeroSub` and `uniqueWhatWeDoBody`. Location pages are the highest collision risk — there are 20+ of them and they share structure, so the copy has to work harder to feel distinct.

**Local prose section rules:**

- 200 words max per location's prose section.
- Town name appears max 3 times in the prose section, and 8–10 times max across the whole page body (including nav, hero, headings, FAQs).
- Each paragraph contains exactly **one** real local entity (a venue, a road, a postcode, a landmark) — never two or three stacked together.
- No sentence may match a sentence on another location page. Reword, don't copy-paste with the town name swapped.

- **Format: WebP.** Compress and convert before committing. JPG/PNG only for original/source assets that haven't been processed yet.
- **Focal point matters.** When an image will be cropped or scaled (hero strips, gallery tiles, OG cards), the core subject must stay centred in the frame at every breakpoint. Analyse the image first, then choose `object-position` / aspect ratio so a downscaled or square crop still leads with the subject.
- **One image = one filename + one alt text.** The rule is per *image file*, not per *placement*. Each unique image gets a content-descriptive filename (`cobham-balloon-arch-pastel.webp`, `safari-second-birthday-cake-table.webp`) and one alt string that describes what's in the photo. No two different image files in the project may share a filename. It's fine for the same file to be referenced from many pages — that's still one filename, one alt.
- **Real events only** (brand book v2). Every photo on the site and social is a real event Laura styled, in the house grade (bright and airy: clean whites, open shadows, accurate colour; no heavy filters, orange skin or crushed blacks). Lead with what she supplies (balloons, backdrops, signage, light-up numbers, plinths, props); faux stems are texture, never the subject. AI-generated images are a last resort for journal articles only, never for the gallery, service pages or social, and never passed off as a real event. The graded set is in Google Drive › River Fox Events › Photos - graded (website).
- **Alt text describes what's actually in the image** — not the page topic, and never the brand name (the brand is already in `<title>` and JSON-LD). Two different image files shouldn't open their alt text with the same 5 words. Bad: "Children's party styling in Surrey by River Fox Events…" repeated across multiple files. Good: each alt opens with what makes that specific photo specific (the cake table, the balloon installation, the venue, the colour palette).
- **Never use `rishi-summer-party-bright-balloon-backdrop.webp`** (Rishi's Summer Party, turquoise/coral/lemon balloons with beach balls). Matt dislikes it (2026-11-08). Don't pick it for any new placement, strip, tile or OG image.
- **Per-page OG images.** The global fallback is `public/social-share.jpg`; journal articles and key pages should override with `ogImage` in `routes.ts` pointing to a per-page `.webp` in `public/og/`.
- **Where Laura's photos are.** About 370 of her photos are in `src/assets/` with one alt each in `src/data/gallery.ts`; reuse those (and their alt) first. **Compression & loading targets:**

- Hero images < 500 KB, gallery images < 200 KB, thumbnails < 100 KB.
- Lossy WebP at quality 75–85.
- `srcset` with at least 3 sizes so smaller viewports don't pull the desktop file.
- Below-fold images use `loading="lazy"`. The hero uses `loading="eager"` with `fetchpriority="high"`.

## Maintenance & change process

Two kinds of copy live in two different places, and the update path differs:

1. **SEO copy (titles, metas) lives in `src/seo/routes.ts`.** Edit that file, then `npm run build` regenerates `dist/*/index.html` automatically. Never hand-edit `dist/`.
2. **Body copy and alt text live in components and data files** (`src/data/locations/*.tsx`, page components, `src/data/articles/`). Editing these triggers a Netlify rebuild on push; HTML always reflects source.

**Whenever body copy changes, or an image is swapped, also check:**

- Does the page's meta description still accurately summarise the body?
- Does the H1 still pair with the new hero copy?
- If an image was replaced, has its alt text been rewritten to describe the *new* image — not just left over from the old one?
- If the page's topic shifted, does its title still front-load the right keyword?
- If a page or schema type was added, run [Google's Rich Results Test](https://search.google.com/test/rich-results) before merging.

Run `npm run build` locally, then `npm run check:links`, and spot-check `dist/<slug>/index.html` before pushing. `check:links` audits the built site: every internal link and `#section` jump, trailing slashes, every redirect target, canonicals, the sitemap, the 404 catch-all, and pages nothing links to. It exits with an error if anything is wrong. Push to `main` deploys to Netlify automatically — there's no manual deploy step, so a broken push goes live.
